# 如何评估 SoundSeed

本指南把三个问题分开回答：找到多少真实事件、产生多少误报、几次反馈后是否改善。v0.1 尚无经过独立验证的真实录音基准成绩。合成演示、单元测试通过和真实应用效果不能互相替代。

## 1. 准备完整人工标注

对待测录音从头到尾标记每一次目标事件的开始和结束，以录音开头为 0 秒，单位为秒。不要只标记系统已经发现的事件，否则召回率和误报会失真。短促的同一次响铃如何合并、连续鸟叫如何分成事件，应在实验开始前确定并始终保持一致。

JSON 格式如下，可参照仓库中的 [示例文件](example-ground-truth.json)：

```json
{
  "version": 1,
  "recording": {
    "name": "doorbell-day-02.wav",
    "date": "2026-09-22"
  },
  "events": [
    { "start": 12.4, "end": 13.2 },
    { "start": 75.1, "end": 76.0 },
    { "start": 184.6, "end": 185.5 }
  ]
}
```

`events` 为完整的目标事件列表；每个区间需满足 `0 ≤ start < end ≤ 录音时长`。没有目标的录音可以使用空数组。`recording.name` 必须与当前 WAV 文件名完全一致；`recording.date` 用于追溯，可省略。文件名校验只能减少误选，仍需确认人工标注确实对应当前文件。

## 2. 指标怎么算

应用使用事件级的一对一匹配，同一个人工事件最多匹配一个预测事件。同一次真实响铃附近的多个重复候选不会全部计为正确。

默认匹配条件满足以下任意一项即可：

- 预测区间与人工区间的重叠时长，占两个区间中较短者时长的 **30% 或以上**。
- 两个区间的开始时间相差 **不超过 0.25 秒**。

程序在满足条件的匹配中寻找最大的一对一匹配。这个口径容许 YAMNet 时间帧带来的边界偏差，是产品的实用诊断指标，**不是 DCASE 官方评分器**。由于较长候选也可能匹配短事件，报告数字时还应抽查候选边界和试听负担。

| 指标             | 定义                 | 回答的问题                 |
| ---------------- | -------------------- | -------------------------- |
| TP               | 成功匹配的预测事件数 | 找到了几次真实声音？       |
| FP               | 没有匹配的预测事件数 | 用户要排除多少误报？       |
| FN               | 没有匹配的人工事件数 | 漏掉了几次？               |
| 精确率 Precision | TP / (TP + FP)       | 展示的候选有多少是对的？   |
| 召回率 Recall    | TP / (TP + FN)       | 真实发生的声音找到了多少？ |
| 误报 / 小时 FP/h | FP / 有效评估小时数  | 每小时录音产生多少误报？   |

当分母为零时，指标不具有通常的统计含义。例如没有目标事件的录音适合评估 FP/h，不适合据其召回率宣称检测性能；没有预测也不能单凭精确率判断系统优秀。请连同 TP、FP、FN 和评估小时数一起看。

## 3. 排除已经教给模型的答案

当前录音中所有用作正例或反例的标注区间构成排除区域。区域先裁剪到录音范围并合并重叠部分，再从总时长扣除。任何与这些区域重叠的预测或人工事件都不参与计分。

例如在 60 分钟录音里圈选了 12 秒教学内容，有效评估时长是扣除合并后教学区域的时长，而不是仍用完整的 1 小时作分母。应用保留被排除事件与候选的数量，便于检查评估范围。

对于同一录音的纠错前后对比，**两侧必须使用同一套最终排除区域**：新增的反例区间在前后两侧都排除。否则把用户手动指出的误报直接移出计分区域，就会制造虚假的改善。更严格的做法是在一份录音中反馈，在另一份完整录音中评估。

从其他文件导入的种子不会按相同时间戳排除当前录音；样例来源标识不同，时间坐标也不同。

## 4. 推荐的可复现实验

### 独立日期测试

1. 在 A 日录音中选定固定数量的正例，例如 3 个；保存初始种子。
2. 在 B 日录音中试听并纠正误报。预先设定反馈预算，例如分别记录 0、1、3、5 次反例反馈后的种子。不要只报告最好的一次。
3. 在 C 日完整录音中分别加载这些种子，使用相同的阈值和匹配规则，导入 C 日完整人工标注并导出结果。
4. C 日不能再次用于挑选样例、调整阈值或选择“最好”的模型。需要调参时，用 B 日数据。
5. 对多个日期、环境及录音设备重复，报告各次结果和总体结果。

可以先完成 A / B 两天的初步实验，但应说明 B 日是否参与过反馈。如果同一原始录音被切成多个文件，它们仍应属于同一个数据划分，不能通过切文件制造独立测试。

### 同录音的交互改善

固定正例、阈值、真值、合并规则和最终排除区域，记录仅正例检索与加入确认反例后的指标。同时报告召回变化和 FP/h 变化：仅靠降低召回率消灭误报，不一定改善使用体验。相似度和分类器的数值没有经过概率校准；同一数字阈值下的对比是固定界面设置的操作性对比，不代表相同概率决策点。

如需比较相同召回率下的误报，应在验证集上选择各方法阈值，再在未使用过的测试集上固定使用。不要在测试集上反复移动滑块并报告最优结果。

## 5. 报告模板

请填写实际测得值，不要把表内占位符当作结果。

| 项目       | 记录内容                                           |
| ---------- | -------------------------------------------------- |
| 版本与环境 | SoundSeed 提交、模型版本、浏览器、CPU、内存        |
| 目标定义   | 例如“一次完整的双音门铃”，含事件切分规则           |
| 数据划分   | 训练 / 反馈 / 测试的日期、来源、设备；是否同源切片 |
| 测试规模   | 录音数量、总小时、有效小时、真实目标事件数         |
| 反馈预算   | 正例数、反例数、反馈来自哪个文件                   |
| 检索设置   | 阈值、匹配容差、最小重叠比例、排除范围             |
| 仅正例结果 | TP、FP、FN、Precision、Recall、FP/h                |
| 加入反例后 | 同上，并同时给出召回和 FP/h 的变化                 |
| 使用成本   | 首次模型加载时间、特征提取时间、纠错等待时间       |
| 失败样例   | 漏检、重复匹配、相似干扰声音及环境变化             |

聚合多个录音时，应先合计 TP、FP、FN 和有效时长，再计算总体比率；不要简单平均短录音与长录音的 FP/h。样本量很小时，展示原始计数比单独展示百分比更有信息。

## 6. 合成演示的定位

合成演示只用于确认：能否加载、圈选、提取特征、添加正反例、更新候选、导出结果和显示评估指标。它的声音由程序生成，分布更简单，不能用来证明真实门铃或鸟叫上的效果。

本项目与 [DCASE 少样本生物声学事件检测](https://github.com/c4dm/dcase-few-shot-bioacoustic) 共享少量样例定义目标的思路，但尚未复现其数据集、协议或官方指标。未来若做研究比较，需要独立接入其正式评测流程。
